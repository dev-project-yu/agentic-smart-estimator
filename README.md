# PI Agentic 스마트 견적서

대학의 PI(Process Innovation, 프로세스 혁신) 프로젝트를 위한 **Streamlit 기반 견적 시뮬레이션 애플리케이션**입니다. 요구사항, 기능 모듈, 수행 기간을 입력하면 프로젝트 복잡도와 작업량을 분석하고 인력 구성, 비용, 수행 가능성을 산출합니다.

인스파이어파트너스의 PI 견적 업무를 시연하기 위한 데모로, 합성·모의 데이터(Synthetic / Mock Data)를 사용합니다. 산출 금액은 실제 계약 견적이 아닌 시뮬레이션 결과입니다.

## 주요 기능

- **요구사항 분석**: Gemini를 활용해 목표, 복잡도, 산출물 등을 분석하며, API를 사용할 수 없으면 규칙 기반 분석으로 전환합니다.
- **모듈별 범위 설정**: 교무 행정, 관리자 승인, 학생 서비스, 기존 시스템 통합, 성과 분석 및 대시보드, 교육 및 지식 전이 모듈을 선택합니다.
- **작업량 및 인력 산정**: 기본 작업량에 복잡도와 일정 계수를 적용하고 역할별 인원과 팀 가용 인월을 계산합니다.
- **비용 및 리스크 평가**: 인건비, 관리비, 위험 버퍼, 이익을 합산하고 수행 가능 여부와 위험 수준을 표시합니다.
- **근거 조회**: 온톨로지 스키마, 지식 그래프 요약, 참고 문서 검색 결과, 분석 단계와 계산 근거를 확인합니다.
- **견적서 다운로드**: 상세 Markdown 견적서와 요약 HTML 견적서를 내려받습니다.

## 기술 구성

| 구분 | 사용 기술 |
| --- | --- |
| 웹 인터페이스 | Streamlit |
| 요구사항 분석 | Google Gen AI SDK, Gemini, 규칙 기반 대체 분석 |
| 참고 문서 검색 | scikit-learn의 TF-IDF 및 코사인 유사도 |
| 지식 그래프 | NetworkX |
| 데이터 및 설정 | 로컬 JSON·Markdown, python-dotenv |

검색은 로컬 참고 문서의 텍스트 유사도를 기준으로 수행하며, 별도의 벡터 데이터베이스는 사용하지 않습니다. 견적 금액은 Python 계산 엔진에서 산출하며, Gemini 분석 결과의 복잡도 값이 계산에 반영됩니다.

## 설치 및 실행

Python 3.10 이상이 필요합니다. 아래 명령은 프로젝트 루트에서 실행합니다.

### 1. 가상환경 및 의존성 설치

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Windows PowerShell에서는 가상환경 활성화 명령을 다음과 같이 바꿉니다.

```powershell
.venv\Scripts\Activate.ps1
```

### 2. 환경변수 설정

`.env` 파일이 없다면 `.env.example`을 복사해 생성합니다. 기존 `.env`가 있다면 필요한 항목만 수정합니다.

```dotenv
GEMINI_API_KEY=your_api_key_here
GEMINI_MODEL=gemini-2.5-flash
```

| 변수 | 설명 |
| --- | --- |
| `GEMINI_API_KEY` | Gemini 사용 시 입력하는 API 키. 규칙 기반 데모만 사용할 경우 비워 둡니다. |
| `GEMINI_MODEL` | 사용할 모델 이름. 미설정 시 코드 기본값은 `gemini-2.5-flash`입니다. |

API 키가 없거나 클라이언트 초기화·API 호출·응답 파싱에 실패하면 규칙 기반 분석을 사용합니다. 예제의 `your_api_key_here`는 실제 키가 아니므로, API 없이 실행할 때는 제거하거나 빈 값으로 설정합니다. 실제 API 키가 담긴 `.env`는 공유하거나 저장소에 커밋하지 않습니다.

### 3. 앱 실행

```bash
python -m streamlit run app.py
```

브라우저에서 터미널에 표시된 주소를 엽니다. 기본 주소는 `http://localhost:8501`입니다.

## 사용 방법

1. 왼쪽 사이드바에서 대학명과 프로젝트명을 입력합니다.
2. 개선하려는 업무와 목표를 프로젝트 요구사항에 작성합니다.
3. 필요한 기능 모듈을 선택하고 수행 기간을 1~12개월로 설정합니다.
4. **견적 생성**을 눌러 작업량, 인력 구성, 비용 내역과 수행 가능성을 확인합니다.
5. 펼침 영역에서 검색 결과와 계산 근거를 확인하고, Markdown 또는 HTML 견적서를 다운로드합니다.

요구사항 예시:

> 교무 행정, 관리자 승인, 학생 서비스 프로세스를 통합하고, 기존 시스템과 연결하여 승인 시간을 줄이고 운영 효율성을 높이고 싶습니다.

## 견적 산정 방식

작업량의 단위는 **인월(PM, Person-Month)**이며 금액의 단위는 원(KRW)입니다.

```text
기초 작업량 = 선택 모듈의 기본 작업량 합계
복잡도 반영 작업량 = 기초 작업량 × 복잡도 계수
계산 작업량 = 복잡도 반영 작업량 × 일정 계수
팀 가용 인월 = 산정 팀 인원 × 수행 개월 수 × 활용률
인건비 = Σ(역할별 인원 × 역할별 월 단가 × 수행 개월 수)
최종 견적 = 인건비 + 관리비 + 위험 버퍼 + 이익
```

- 일정 계수는 1개월 1.55, 2개월 1.35, 3개월 1.00이며, 장기 일정에는 별도 계수를 적용합니다.
- 활용률은 1~2개월 60%, 3~6개월 72%, 7~12개월 75%입니다.
- 일반 산정에서는 관리비가 인건비의 12%, 위험 버퍼가 기간에 따라 인건비의 6~18%, 이익이 소계의 18%입니다.
- 수행 불가로 판정되면 관리비 14%, 위험 버퍼 22%, 소계 대비 이익 20%를 적용합니다.
- 수행 가능성은 작업량 대비 가용 인월과 기간별 팀 규모 제한으로 판정합니다. 상세 기준은 `pricing_engine.py`에 정의되어 있습니다.

## 프로젝트 구조

```text
.
├── app.py                       # Streamlit 화면 및 견적서 다운로드
├── agent_service.py             # Gemini 호출 및 규칙 기반 분석
├── pricing_engine.py            # 작업량·인력·견적·수행 가능성 계산
├── semantic_layer.py            # 모듈·인력 단가·모의 프로젝트 데이터 접근
├── knowledge_graph.py           # 관계 그래프 생성 및 요약
├── ontology.py                  # 온톨로지 데이터 모델 정의
├── rag_service.py               # 참고 문서 로딩 및 TF-IDF 검색
├── data/
│   ├── modules.json             # 기능 모듈, 기본 작업량, 역할, 의존성
│   ├── personnel_costs.json     # 역할별 월 인건비
│   ├── mock_projects.json       # 모의 프로젝트
│   ├── outcomes.json            # 성과 데이터
│   └── reference_documents.md   # 검색용 참고 문서
├── tests/
│   └── test_pricing.py          # 견적 엔진 단위 테스트
├── architecture.html            # 아키텍처 설명 문서
├── code_review.html             # 코드 리뷰 문서
├── dev_intent_analysis.html      # 개발 의도 분석 문서
├── .env.example                 # 환경변수 예시
└── requirements.txt             # Python 의존성
```

## 테스트

```bash
python -m unittest discover -s tests -v
```

견적 엔진의 기간별 금액 변화, 동일 입력에 대한 재현성, 팀 가용 인월, 단기 일정의 수행 불가 판정을 검증합니다. Gemini 응답과 전체 웹 화면은 이 테스트의 검증 범위에 포함되지 않습니다.

## 데이터 및 정책 수정

- 기능 범위와 기본 작업량은 `data/modules.json`에서 수정합니다.
- 역할별 월 단가는 `data/personnel_costs.json`에서 수정합니다.
- 검색 근거는 `data/reference_documents.md`에 추가합니다.
- 일정 계수, 활용률, 비용 비율과 수행 가능성 기준은 `pricing_engine.py`에서 수정합니다.

일부 원본 데이터의 모듈명은 중국어로 저장되어 있으며, 화면의 선택 항목은 한국어로 표시합니다. 모듈명을 변경할 때는 `app.py`의 표시명 매핑과 기본 선택값도 함께 확인합니다. 데이터나 환경변수를 수정한 뒤에는 앱을 재시작해 캐시된 서비스를 다시 생성합니다.
